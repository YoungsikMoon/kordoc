# 기관팩 — 우리 기관 서식으로 문서 만들기

kordoc 에는 중앙부처 52곳의 실측 서식만 들어 있습니다. 지자체·공공기관 서식은 기관마다 다르고 수백 곳이라 kordoc 에 다 담을 수 없습니다.
기관팩(`.kpack`)은 이 문제를 반대로 풉니다. **사용자가 자기 기관 문서 몇 건을 주면 kordoc 이 그 서식을 담은 파일 하나를 만들고**,
그 파일을 주면 같은 서식으로 새 문서를 만듭니다. 서식을 kordoc 에 넣지 않으므로 기관 로고나 내부 문서가 npm 패키지에 실리지 않습니다.

## 빠른 시작

```bash
# 1. 같은 종류 문서(예: 보고서) 몇 건으로 팩 만들기
kordoc pack build 보고서1.hwpx 보고서2.hwpx 보고서3.hwpx --name 광양시 -o 광양시.kpack

# 2. 요약과 작성 요령 보기
kordoc pack info 광양시.kpack --guide

# 3. 작성 요령대로 쓴 원고를 팩 서식으로
kordoc generate 새보고서.md --pack 광양시.kpack -o 새보고서.hwpx
```

`--name` 은 팩 이름(표시용)이고 문서에 들어가지 않습니다. 종류(`--kind`)가 하나인 팩은 `generate` 때 `--pack-kind` 를 주지 않아도 됩니다.
보도자료처럼 다른 종류는 종류 이름을 붙여 같은 팩에 더합니다.

```bash
kordoc pack build 보도1.hwpx 보도2.hwpx --name 광양시 --kind press --into 광양시.kpack
kordoc generate 보도자료.md --pack 광양시.kpack --pack-kind press -o 보도자료.hwpx
```

## 견본 고르기

팩의 품질은 견본이 정합니다.

| 할 것 | 하지 말 것 |
| --- | --- |
| 같은 종류 문서를 **3~10건** (3건부터 교차 재현으로 대표를 고릅니다) | 보고서·보도자료·공고문을 한 종류로 섞기 — 종류마다 `--kind` 로 나눠 만들기 |
| 종류 이름은 자유(영문 소문자·숫자·한글·붙임표 20자) — `report`(기본)·`press`·`notice`(공고문)처럼. 이름은 고르기용일 뿐 생성 방식은 같습니다 | |
| 최근 결재 문서, 한 부서보다 여러 부서 문서 | 손으로 글자 크기를 많이 바꾼 문서 한 건만 |
| 한글에서 **HWPX** 로 저장한 파일 (HWP 는 한글에서 다른 이름으로 저장 → HWPX) | 표 하나짜리 신청서·서식 — 이런 문서는 `fill_form`·`patch_document` 가 맞습니다 |

만들기 결과의 경고를 읽으세요.

- **견본별 일치도**: 견본마다 역할별 다수결 서식과 맞는 비율입니다. **50% 미만**이면 "다른 서식으로 보이는 견본 N번째" 경고가 붙습니다 — 그 견본은 역할별 서식(□·ㅇ 글꼴·크기 등)이 다른 견본들과 많이 다르니 다른 종류 문서가 섞였는지 확인하세요. 50~80%는 같은 서식에 손으로 바꾼 곳이 있는 정도입니다.
- **비운 견본이 원 견본과 다르게 읽힘**: 대표 견본에서 원문 글을 비운 뒤 다시 읽었을 때 역할 판정이 달라진 경우입니다. 팩은 이때 원 견본 글을 ○ 로 가린 판으로 바꿔 판정을 맞추고, 그래도 다르면 이 경고를 남깁니다. 견본을 더 넣어 다시 만드세요.
- **남은 글**: 비운 견본에 남은 머리말·꼬리말·고정 칸 글입니다. 남에게 주기 전에 확인하세요.
- **그림 N개**: 로고 등 견본 그림입니다. 남에게 줄 때 사용 허락을 확인하세요.

## 원고 쓰기

팩마다 `guide.md`(작성 요령)가 들어 있습니다. `kordoc pack info 팩.kpack --guide` 로 보고, 그 안의 **원고 예**를 꼴 그대로 두고 내용만 바꿔 씁니다.
역할 규칙은 kordoc 견본 모드(`kordoc generate --template`)와 같습니다.

| 원고 | 들어가는 자리 |
| --- | --- |
| 첫 줄 `# 제목` | 견본 제목표 (공고문 머리 상자면 다음 줄 도입 문장·날짜·발신 명의까지 같은 상자에) |
| 제목 다음 담당 줄 (`담당 : 홍길동 ☎ 1234` 처럼 ☎ 또는 '담당:') | 견본 담당 칸 |
| 제목 다음 `> 한 문장` | 견본 요약 상자 |
| `## 장 제목` | 견본 장 띠 (번호는 견본 꼴을 따라 1·2·3 / 가·나·다 / Ⅰ·Ⅱ 자동, `## 3. 제목` 처럼 직접 써도 됨) |
| `□` · `ㅇ` · `-` · `·` 로 시작하는 줄 | 1~4단계 (부호 모양은 견본 것을 따릅니다. 작성 요령에는 그 팩 견본에 있는 단계만 나옵니다 — 없는 단계는 이웃 단계 서식으로) |
| `※ 참고` | 참고 문구 |
| GFM 표 | 견본 표 서식 (머리행·본문·합계 행) |
| `## 참고1 제목` | 견본 참고 띠 |

견본에 없는 역할은 가까운 서식으로 대신하고 경고합니다. 그림·각주·인라인 수식은 넣지 않습니다.

- **날짜로 시작하는 줄**: `2026. 3. 1.` 처럼 숫자와 마침표로 시작하는 줄은 마크다운 번호 목록으로 읽혀 항목 부호가 붙습니다. `2026\. 3. 1.` 처럼 마침표 앞에 `\` 를 붙입니다(생성 때 경고합니다).
- **표기·문체 지적**: 생성할 때 표기법·문체 지적(쌍점 띄어쓰기, `~` 등)이 함께 나옵니다(많으면 일부만 — 전부는 `kordoc lint 원고.md`). 참고용이라 파일은 만들어집니다. 기관 관행과 다르면 사용자에게 물어 정합니다. 공고문 도입 문장의 "~합니다" 처럼 문서 종류에 맞는 문체는 도구가 지적해도 고치지 않습니다.
- **서식 옵션**: `--pack` 은 `--preset`·`--notice-head`·`--h2-marker`·글꼴·쪽 옵션과 함께 쓰지 않습니다(서식은 팩이 정합니다). 날짜·발신 명의는 원고에 일반 줄로 씁니다.
- **팩 견본 눈으로 보기**: `kordoc pack info` 는 요약만 보여 줍니다. 팩 견본 자체를 보려면 `.kpack` 을 zip 으로 풀어 `kinds/<종류>.hwpx` 를 `kordoc render` 합니다.

## AI 에이전트 절차 (MCP)

MCP 도구 세 개를 씁니다: `build_agency_pack` · `agency_pack_info` · `generate_document`(`pack_path`).

1. **사용자가 기관 문서 여러 건을 주며 "우리 기관 서식으로 계속 쓰고 싶다"고 하면** → 같은 종류끼리 묶어 `build_agency_pack`
   (`sample_paths`, `name`, `kind`, `output_path`). HWP 파일이면 한글에서 HWPX 로 저장해 달라고 요청합니다.
2. 결과의 경고(다른 서식으로 보이는 견본·남은 글·그림)를 **사용자에게 그대로 알립니다.**
3. **사용자가 팩을 주며 그 서식으로 써 달라고 하면** → 먼저 `agency_pack_info` 로 작성 요령을 읽습니다.
4. 요령의 원고 예 꼴대로 원고를 쓰고 `generate_document` 에 `pack_path`(필요하면 `pack_kind`)를 줍니다. 프리셋·글꼴·쪽 옵션은 함께 주지 않습니다(오류).
5. `render_document` 로 결과 첫 쪽과 견본 **본문 첫 쪽**(표지·점검표 다음)을 나란히 렌더해 눈으로 확인합니다. 볼 것: 제목 크기·색·위치, 공고문 머리 상자(도입·날짜·발신 명의), 장 띠 번호, □·○ 부호와 들여쓰기, 표 머리 색, 형광펜·색 강조가 엉뚱한 줄에 칠해지지 않았는지. `validate`·다시 읽기는 글만 보므로 이런 결함을 못 잡습니다.
6. 팩 결과가 견본과 다르면 같은 원고를 견본 하나로(`generate_document` 의 `template_path`) 만들어 비교하고, 더 나은 쪽을 사용자에게 보여 줍니다. 팩은 견본을 더 넣어 다시 만들 수 있습니다.

구분할 것:

| 요청 | 도구 |
| --- | --- |
| "이 문서 서식대로 **이 문서를** 고쳐 써줘" (견본 한 건, 줄·표 구조 그대로) | `parse_document` → `patch_document` |
| "이 문서처럼 **새 문서**를 써줘" (견본 한 건) | `generate_document` 의 `template_path` |
| "우리 기관 서식으로 **앞으로 계속**" (견본 여러 건) | `build_agency_pack` → `generate_document` 의 `pack_path` |
| 신청서·서식 빈칸 채우기 | `fill_form` |

## 라이브러리 API

```ts
import { readFileSync, writeFileSync } from "fs"
import { buildAgencyPack, loadAgencyPack, packTemplate, markdownToHwpx } from "kordoc"

const { pack, manifest, guide } = await buildAgencyPack("광양시", [
  { data: readFileSync("보고서1.hwpx") }, { data: readFileSync("보고서2.hwpx") }, { data: readFileSync("보고서3.hwpx") },
])
writeFileSync("광양시.kpack", pack)

const p = await loadAgencyPack(readFileSync("광양시.kpack"))
const hwpx = await markdownToHwpx(원고, { template: packTemplate(p, "report") })
```

`buildAgencyPack(name, samples, into?)` 의 `samples` 항목은 `{ data, kind? }`(기본 `report`), `into` 에 읽은 팩을 주면 종류를 더합니다.

## 팩이 하는 일

팩은 **코드 없는 zip** 입니다.

| 파일 | 내용 |
| --- | --- |
| `pack.json` | 기관 이름·만든 날·kordoc 판, 종류마다 견본 수·대표·역할·없는 역할·견본별 일치도·자기 검사·남은 글·그림 수, 견본 지문(SHA-256) |
| `kinds/<종류>.hwpx` | 대표 견본을 **비운 판** — 서식·틀·로고만, 원문 글 없음 |
| `guide.md` | 작성 요령과 원고 예 |

1. **대표 고르기** — 견본마다 역할(제목표·담당·요약·장·□·ㅇ·-·※·본문)별 서식을 읽어 역할·속성(글꼴·크기·굵기·정렬·줄간격)마다 다수결을 냅니다.
   다수결과 60% 이상 맞는 견본 중 상위 6개를 후보로, **다른 견본들의 글을 그 후보로 다시 만들어 원본과 대조한 점수**(교차 재현)로 다시 줄 세웁니다.
   견본 하나를 아무거나 쓰면 같은 기관 문서도 재현율이 46~82%로 흔들렸습니다.
2. **비우기** — 대표 견본이 가진 역할을 한 번씩 쓰는 골격 원고로 견본 모드 생성을 한 번 돌립니다. 생성기가 원문 본문을 버리고, 안 쓰는 그림·미리보기 그림을 뺍니다.
   여기에 작성자·날짜 메타를 비우고, 결재선 칸에 남은 이름·전화를 ○ 로 바꾸고, 직위 앞 부서 이름을 뺍니다("도시정책과장 : 홍길동☎…" → "과장 : ○○○☎○○○○").
3. **다수결로 맞추기** — 견본이 셋 이상이면 단계(□·ㅇ·-·)·본문·※ 원형을 견본들의 과반이 같은 서식(크기·굵기·글꼴·정렬·줄간격·문단 간격)으로 맞춥니다. 대표 견본 한 건에만 있던 손 조정이 새 문서로 옮지 않습니다.
4. **자기 검사** — 비운 견본을 다시 읽어 역할·서식이 원 견본과 같은지 봅니다. 다르면 다음 후보를 쓰고, 모두 다르면 가장 나은 것을 쓰되 경고합니다.
5. **읽기** — 팩은 남이 준 파일로 다룹니다. zip 크기·항목 수, 허용 파일(`pack.json`·`guide.md`·`kinds/*.hwpx`)만, 형식 판을 검사하고, 견본은 생성 때 견본 방어를 한 번 더 거칩니다.

## 검증

재현율은 공문서 생성 재현 벤치(`bench/gen-repro.mjs`)와 같은 채점기로 잽니다. 문단을 글 순서로 짝지어 역할마다 글꼴·크기·굵기·색·정렬·줄간격·문단 위/아래 간격을 대조합니다.
모든 수치는 **그 문서를 뺀 나머지 견본으로 만든 팩**으로 잰 것입니다(처음 보는 문서). 대조군은 기관 서식 없이 쓰는 기본 보고서 프리셋, 상한은 그 문서 자신을 견본으로 쓴 것입니다.

| 문서 묶음 | 원고 | 기본 보고서 | **기관팩** | 상한 | 글꼴·크기·굵기 (기본 → 팩) |
| --- | --- | --- | --- | --- | --- |
| 서울시 방침서 16건 중 원고 있는 5건 | 사람이 옮긴 원고 | 68.3% | **74.3%** | 80.0% | 53.5% → **75.3%** |
| 광양시 보고서 1안 9건 (기여 제안 #173 의 생성기로 만든 문서) | 같은 원고 | 77.1% | **94.5%** | 95.4% | 38.8% → **85.9%** |
| 광양시 누리집 공고문 4건 (같은 양식) | kordoc 이 읽은 원고 | 58.3% | **71.1%** | 74.4% | 24.8% → **55.2%** |

- **읽는 법**: 100% 는 견본 하나로는 닿을 수 없습니다 — 작성자가 문단마다 줄간격·간격을 손으로 바꾸므로, 그 문서 자신을 견본으로 써도(상한) 80% 안팎입니다. 사람이 쓴 문서로 잰 서울 방침서·광양 공고문 수치가 실제 사용에 가깝습니다. **광양 보고서 1안은 정답이 사람 문서가 아니라 생성기로 찍은 문서**(서식이 고르게 맞음)이고, 그 생성기 전용 부품(설명상자·둥근 상자·표 제목 띠)은 원고에서 빼고 쟀으므로 실제 광양 보고서에서는 이보다 낮게 나옵니다. 표본도 문서 4~9건이라 한두 건에 몇 점씩 흔들립니다.
- **비우기 무손실**: 서울 방침서 16견본 × 원고 9건 = 144건 모두 원 견본으로 만든 것과 서식이 같습니다(채점 100%). 골격 원고로 비운 판이 어긋나는 한 견본(제목 없이 요약 상자만 있는 꼴)은 가린 판으로 바뀌어 원 견본과 바이트까지 같습니다.
- **개인정보 점검**: 견본마다 팩을 만들어 원문의 이름·전화·본문 글(8자 조각)이 팩에 남는지 봅니다 — 서울 16건·광양 9건 모두 통과.
- 표 하나짜리 공고문(광양시 공시송달 5건)은 바꿀 역할이 없어 기본·팩·상한이 모두 같습니다(62.5%). 이런 문서는 `fill_form`·`patch_document` 를 씁니다.

재현:

```bash
npm run build
node bench/pack-repro.mjs                       # 서울 방침서(bench/corpus-gen, git 밖) 하나 빼기
node bench/pack-repro.mjs --dir=<같은 종류 HWPX 폴더>   # 원고 없이 kordoc 이 읽은 마크다운으로
```

## 한계

- 견본 모드의 한계를 그대로 갖습니다: 그림·각주·인라인 수식은 넣지 않고, 표지·목차는 만들지 않으며, HWPX 견본의 본문 구역 하나만 씁니다.
- 숫자 위계(1. → 1) → ①)만 쓰는 문서는 견본 모드에 숫자 위계 원형이 없어 팩 효과가 작습니다(서울 방침서 1건: 기본 67.6% · 팩 69.8%).
- 견본 훑기가 역할을 잘못 읽는 견본(제목표를 담당 칸으로 읽는 등)은 자기 검사가 경고합니다. 견본을 더 넣으면 다른 견본이 대표가 됩니다.
- 본문에 놓인 그림(쪽 배경 그림 포함)은 팩에 담기지 않습니다. 쪽 머리·꼬리·바탕쪽 그림만 남습니다.
- 공고문 머리 상자(제목·도입 문장·날짜·발신 명의를 표 칸 하나에 담은 꼴)는 칸 안 문단을 자리로 나눠 채웁니다 — 원고는 `# 제목` 다음 줄에 도입 문장, 날짜(`2026\. 5. 20.`), 발신 명의를 차례로 씁니다. 제목 위 작은 사업명 줄이 있는 견본이면 `# 제목` 바로 다음에 `- 사업명 -` 줄을 씁니다(안 쓰면 그 자리는 빕니다).
- 제목 줄은 한 가지 글자 모양으로 들어갑니다 — 견본 제목이 낱말마다 색·음영이 다르면(사업명 파랑 + "모집 공고" 검정) 새 제목은 한 색이 됩니다.
- HWP(5.x) 견본은 받지 않습니다 — 한글에서 HWPX 로 저장하세요.

## 팩을 남에게 줄 때

팩에는 원문 본문·작성자 정보·결재선 이름·전화가 들지 않지만, **기관 로고·머리말·꼬리말 같은 고정 요소는 들어 있습니다**.
`kordoc pack info` 의 "남은 글"·"그림" 항목을 확인하고, 로고가 있으면 기관의 사용 허락 범위 안에서만 주고받으세요.
